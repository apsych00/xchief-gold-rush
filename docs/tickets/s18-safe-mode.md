TICKET S18: safe mode ("under attack") for the box.

Read AGENTS.md, .claude/agents/builder.md, docs/TRACKER.md (S2, S18), server/index.js, server/limits.js (S2, must be merged first), server/alerts.js, ops/index.html, Caddyfile, docs/box-deploy.md, docs/admin-requirements-box.md. Never open a file named .env. Never commit. Work only in this worktree.

The threat: a script spawning many headless browsers or raw sockets, from one IP or from rotating IPs. S2 handles one IP. Safe mode handles the rest by shrinking what an unknown client can do until the traffic settles, without touching players who are already in.

Decisions (do not redesign):
1. A server-wide mode with three levels, held in memory and mirrored to a row in `public.settings(key, value)` so it survives a restart: `normal`, `guarded`, `locked`. Changed by an operator through `scripts/safe-mode.mjs <level>` (writes the row; the server polls it every 5 s) and automatically as below. `/status` shows the level and the reason; `/ops` shows it as a banner (red for locked).
2. `guarded`: new anonymous players are refused with `{type:'error', code:'safe_mode', retry_ms: 30000}` unless the socket presents a valid player token or a valid device token older than 10 minutes; kiosks unaffected; OTP requests allowed but halved limits; leaderboard pushes throttled to once per 5 s. `locked`: additionally every new web socket is closed with 4503 after the welcome-less refusal frame, except kiosks and sockets with a token issued before the lock; existing sockets keep playing.
3. Automatic escalation (server/safemode.js): if new socket connections exceed 300 per minute, or new anonymous players exceed 100 per 10 minutes, or the S2 block list has more than 20 IPs, escalate one level and post an alert; de-escalate one level after 10 minutes below half of those thresholds. Thresholds are constants with env overrides; document them against the capacity targets (100 concurrent, 2,000 a day) so normal expo traffic never trips them.
4. Cloudflare side, documented not coded (docs/box-deploy.md "If the box is attacked" and docs/admin-requirements-box.md section 2): a rate-limiting rule on `/ws` and `/api/*` (e.g. 60 requests per minute per IP), Bot Fight Mode on, and the "I'm Under Attack" security level as the manual last resort (a JS challenge on every new visitor; players mid-game keep their socket). State the exact clicks.
5. Runbook: what an operator sees on `/ops`, the one command to lock and to return to normal, and how to tell an attack from a busy booth (kiosk rounds continue in both; anonymous signups spike only in an attack).
Tests: unit for the escalation state machine with an injected clock; integration: guarded refuses a new anonymous player and accepts a token holder and a kiosk; locked closes with 4503 and keeps an existing socket playing; the settings row is honoured after a restart; /status shows the level.
