Decisions (do not redesign):
1. Table `public.tournaments(id text primary key, title text not null, starts_at timestamptz not null, ends_at timestamptz not null, prize_title text not null, prize_image text not null, broker_bonus text, created_at)`; constraint `ends_at > starts_at`; no two tournaments overlap (exclusion constraint on tstzrange). Seed (db/seed.sql): `t1` "Gold Rush Week 1" 2026-09-16 00:00 to 2026-09-21 00:00 Asia/Dubai, prize_title "First prize", prize_image "/prizes/week1.png"; `t2` 2026-09-21 to 2026-09-24. Dubai time stored as timestamptz.
2. Every settled round belongs to the tournament running at its `end_at`: `rounds.tournament_id text references tournaments(id)`, set inside `settle_round` from `now()`; null when no tournament is running (rounds then count for nothing). A player's record per tournament is the peak balance reached inside it: table `public.tournament_scores(tournament_id, player_id, record int, updated_at, primary key (tournament_id, player_id))`, upserted by `settle_round` when `coins` exceeds the stored record. `players.record` stays as the all-time value.
3. `public.current_tournament()` returns the row whose range contains now(), else null. `public.leaderboard(p_tournament text default null)` ranks `tournament_scores` for that tournament (default current), verified emails only, masked `display`, `record`, `rank`; returns nothing when no tournament is running. The server's leaderboard push and the `leaderboard` frame gain `tournament: {id, title, starts_at, ends_at, prize_title, prize_image, broker_bonus}` and `tournaments: [{id, title, starts_at, ends_at, status: 'past'|'live'|'upcoming'}]`. A new `tournament` request frame with `{id}` returns that tournament's final board the same way.
4. Adjusting tournaments is SQL only, documented in docs/box-deploy.md "Daily habits" with the exact `insert`/`update` one-liners via `docker compose exec db psql`; the server reads them live (no restart, no cache older than the leaderboard's 1 s throttle).
