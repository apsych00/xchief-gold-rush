TICKET K1: the open kiosk route - `<campaign URL>/kiosk` sets a kiosk up by itself and keeps it across reloads, crashes and reboots.

Never open a file named .env. Never commit. Work only in this worktree.

The owner's decision: for the two-day exhibition, ease of setup wins over the secret-in-URL model. Anyone who opens `/kiosk` gets a working kiosk. This is an accepted leak; the route is switched off after the exhibition and only the web experience survives.

Decisions (do not redesign):
1. Route: `GET /kiosk` (the SPA serves it like `/claim/<token>`; Caddy's try_files already falls back to index.html; add the same to the Vite dev server if needed). The client on `/kiosk` reads `localStorage['xchief.kiosk']` = `{id, secret, label, provisioned_at}`. If present, it authenticates as that kiosk exactly as `?k=<secret>` does today (reuse the same code path; `IS_KIOSK` is true on `/kiosk`). If absent, it calls `POST /api/kiosk/provision` and stores the answer, then authenticates.
2. `POST /api/kiosk/provision` (public, no auth): creates a kiosk row with a random 32-char base64url secret (stored hashed like every kiosk secret) and a label `open-<yyyymmdd>-<4 random chars>`, and returns `{id, secret, label}`. Guarded by: env `KIOSK_OPEN_PROVISION=1` (default 0; 1 in .env.box.example with a comment saying it is the exhibition switch and must be 0 afterwards), S2's per-IP window (provision counts as an anonymous auth, 10 per 10 minutes per IP by default), and a hard cap `KIOSK_OPEN_MAX=50` open kiosks in total (refuse with 429 `kiosk_cap` beyond it). When the switch is off the route answers 404 and `/kiosk` shows the existing "Kiosk not configured. Tell the booth staff." state.
3. Persistence: the kiosk's identity lives in localStorage on that device; the kiosk's session (coins, streak, prize state) already lives on the server keyed by kiosk id (C1), so a reload, a browser crash or an OS reset resumes exactly where it was after the client re-authenticates. Prove it: E2E that provisions on `/kiosk`, plays two rounds, reloads, and sees the same coins and streak; and a second browser context on `/kiosk` gets a different kiosk (different label) with a fresh session.
4. Existing `?k=<secret>` kiosks keep working unchanged (the seeded dev kiosk and the E2E suite depend on it).
5. Operator visibility: `/status` gains `kiosks: {seeded, open}` counts; `scripts/export-coupons.mjs` (or the kiosk listing script if one exists) shows the label. docs/box-deploy.md gets an "Open kiosk route" paragraph: what it is, the two env switches, how to turn it off after the exhibition (`KIOSK_OPEN_PROVISION=0` and restart), and that decommissioning the kiosks means deleting the rows with the labels starting `open-`.
