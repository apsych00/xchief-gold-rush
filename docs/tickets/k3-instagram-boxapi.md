Decisions (do not redesign):
1. Env: `BOXAPI_TOKEN` (Bearer), `BOXAPI_BASE` (default `https://boxapi.ir/api/instagram/`), `INSTAGRAM_HANDLE` (ours, e.g. `xchief`), `INSTAGRAM_PROFILE_URL` stays. 2. Flow: (a) the Instagram task row asks for the player's handle (an input with `@` prefix, trimmed, lowercased, 1-30 chars of `[a-z0-9._]`, validated client and server); (b) `{type:'instagram_start', handle}` stores the handle on `instagram_accounts` (keyed by the player, `handle` unique, `verified_at` null) and answers `{type:'instagram_started', profile_url, app_url}` where `app_url` is `instagram://user?username=<INSTAGRAM_HANDLE>` and `profile_url` the web URL; the client opens `app_url` (falls back to `profile_url` after 1.5 s if the app did not take over; standard deep-link pattern) in a new tab; (c) when the tab regains focus, and again on a "I followed, check" button, the client sends `{type:'instagram_check'}`; (d) the server resolves our own numeric id once (`user/get_info_by_username {username: INSTAGRAM_HANDLE}`, cached in memory for 24 h), then checks the follow with `user/get_following {id: <their id>, count: 200}` after resolving their id the same way; if our id is in the list the task is released through `release_task_reward` (once per Instagram account, device and email, B13's rules) and the answer is `{type:'instagram_result', ok:true}`; if their account is private or the list does not contain us, `{ok:false, reason:'not_following'|'private'|'not_found'}` and the row shows the matching copy ("We could not see the follow yet. Follow @xchief and tap check again." / "Your account is private; make it public for a moment or ask the booth staff."). At most 1 check per 20 s per player (in-memory), and every BoxAPI call is logged with the handle and the outcome, never the token.
3. Abuse: a handle can be claimed by one player only (unique); changing the handle after a successful verify is refused; `instagram_check` counts against S2's per-socket query budget.
