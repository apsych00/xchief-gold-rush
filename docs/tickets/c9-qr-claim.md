The product rule (from the owner): a visitor who predicts correctly N times in a row sees a QR code with a one-time link and this text (Persian first, English under it): "تبریک! شما برنده بونوس ۱۰۰ دلاری ایکس‌چیف شدید. برای دریافت هدیه اسکن کنید:" / "Congratulations! You won the xChief $100 bonus. Scan to claim your gift:". Scanning opens the claim page. The link works once. The visitor must enter their email to receive the bonus code; then a gift card with the code is shown. The QR stays on the kiosk for 20 s with a "I've scanned it" button; the button or the timer resets the kiosk.

Decisions (do not redesign):
1. Streak target: `KIOSK_STREAK_TARGET` env (default 5; the owner may set 10), read by the server and passed into the SQL that issues the prize (`settle_kiosk_round` takes it as a parameter or reads a `public.settings` row `kiosk_streak_target`; choose the settings row, mirrored from env at boot, so a running box can change it with one SQL update). The client reads the target from the `kiosk_session` frame (`streak_target`) for its "N in a row" copy; nothing client-side decides the prize.
2. Coupon lifecycle: `coupons.status` gains `reserved` (check constraint updated). At the winning settle the coupon is reserved, not claimed, and a row is inserted in `public.claim_links(token text primary key, coupon_id uuid not null unique references coupons(id), kiosk_id uuid not null, created_at timestamptz not null default now(), expires_at timestamptz not null, email text, claimed_at timestamptz, claimed_ip inet)` with `token` = 32 random base64url chars from `gen_random_bytes(24)`, `expires_at = now() + interval '24 hours'`. The winning `round_settled` and the `kiosk_session` frame carry `claim_url` (absolute, built from `PUBLIC_URL` env, e.g. `https://goldrush.xchief.academy/claim/<token>`) and `claim_expires_at`; they never carry the code. The existing 60 s sweep releases coupons whose link expired unclaimed: `status='available'`, link row kept with `expired_at` for the audit. `coupons_exhausted` (C8) counts `available` only; `/status` counts add `reserved`.
3. Kiosk screen (replaces the WIN modal's code): QR (npm `qrcode`, the one allowed new dependency, rendered to an SVG data URL client-side from `claim_url`), the two-language text above, a 20 s ring or bar countdown reusing the existing idle-countdown styles, and one button "اسکن کردم / I've scanned it". Button press or countdown end sends `kiosk_reset` (which now voids any open round, C10) and the booth returns to attract. Activity during the 20 s does not extend it. `window.__xchief.kioskTiming.QR_MS = 20000` for tests. The C8 no-codes modal and the exhausted-pool streak behaviour (B14) are unchanged.
4. Claim page at `/claim/<token>`: the SPA serves it (Caddy already falls back to index.html; the client routes on `location.pathname`, no router library). It is a web-mode screen with no game UI: title "Your xChief $100 bonus", the three steps in one short list ("Enter the email you want the bonus sent to", "Your gift card appears here", "We also email it to you"), an email field and a "Get my code" button. HTTP: `GET /api/claim/<token>` returns `{state:'ready'|'claimed'|'expired'|'invalid', expires_at, email_masked}`; `POST /api/claim/<token> {email}` is one atomic SQL call `claim_prize(p_token, p_email, p_ip)` that fails with `already_claimed`, `expired` or `invalid` and otherwise sets `claimed_at`, `email`, marks the coupon `claimed` and returns the code. The response renders the gift card: reuse the WIN modal's card styles with the code in `.kiosk-code`, the email it was sent to, and "Screenshot this or check your inbox". The server then emails the code through server/otp.js's Elastic sender with a plain-text template (subject "Your xChief $100 bonus code"); a mail failure is logged and does not undo the claim. Reopening a claimed link shows "This gift was claimed by a****n@example.com" and nothing else; expired shows "This link has expired. Ask the booth staff." Rate limit: `POST /api/claim/*` 5 per 10 minutes per IP through S2's window if merged, else a local window with the same shape.
5. Copy: every new string in both `fa` and `en` in src/i18n.js; the kiosk shows both languages at once (the QR text), the claim page follows the browser language with the existing switcher. Design fidelity rule applies; screenshots of the kiosk QR screen and the claim page (ready, claimed, expired) to docs/reports/c9/.
