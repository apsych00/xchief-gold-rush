Decisions (do not redesign):
1. Adapter `server/instagram.js` with one exported function `checkFollows({ handle })` returning `{ok:true, follows:boolean, ig_user_id}` or `{ok:false, code}`; it uses the Instagram Graph API for business accounts: `GET https://graph.facebook.com/v21.0/{IG_BUSINESS_ID}?fields=business_discovery.username({handle}){followers_count}` is NOT a follow check, so do not use it; the follow check is `GET /{IG_BUSINESS_ID}/followers` is not exposed either. Use the only supported path: Instagram Login (Basic Display successor) where the player authorises our app, we exchange the code for a user token, read the player's `user_id` and `username`, and then verify the follow by asking the business account's `/{IG_BUSINESS_ID}?fields=followers_count` before and after is unreliable; therefore the decision is: verification = the player completes Instagram OAuth with our app (proves a real Instagram account, bound one-per-device-or-email) AND the app checks `GET /{ig_user_id}?fields=id,username` succeeds. Follow itself is requested by deep-linking to our profile after OAuth. Document plainly in docs/box-deploy.md that Instagram does not expose "does X follow Y" to third parties and that the reward is bound to a verified Instagram account, once per account, per device and per email. Table `public.instagram_accounts(ig_user_id text primary key, username text, player_id uuid, device_id uuid, verified_at)`; a second player or device presenting the same `ig_user_id` is refused with `already_claimed`.
2. Env (`.env.box.example`, all optional, adapter reports `not_configured` when any is missing): `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`, `INSTAGRAM_REDIRECT_URI` (`https://goldrush.xchief.academy/api/instagram/callback`), `INSTAGRAM_PROFILE_URL`. HTTP: `GET /api/instagram/start?token=<player token>` redirects to the Instagram authorise URL with `state` = HMAC of the player id; `GET /api/instagram/callback` exchanges the code, stores the account, releases the `instagram` task through the same server-side path as B6, and redirects to `/?ig=done` or `/?ig=<error code>`. The client task row for kind `instagram` opens `/api/instagram/start` in the same tab and shows the pending, done and failed states from the query parameter (copy: "Connecting Instagram", "Followed! +300 coins", "Instagram did not confirm. Try again.").
3. `/status` gains `instagram: 'configured' | 'not_configured'`. Rate limit the two endpoints with S2's per-IP window.
4. A fake Instagram server for tests (`test/fakes/instagram.mjs`) implementing the authorise redirect, the token exchange and the `/me` read, selected by `INSTAGRAM_API_BASE` (default the real host).
