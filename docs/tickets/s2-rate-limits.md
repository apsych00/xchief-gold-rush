TICKET S2: per-socket and per-IP rate limits in the game server.

Read AGENTS.md, .claude/agents/builder.md, docs/TRACKER.md (S2, S18), docs/box-architecture.md 5b (capacity targets: 100 concurrent, 2,000 a day), server/index.js (createServer, wss, handleAuth, handleFrame, heartbeat, BACKPRESSURE_BYTES), server/otp.js, server/ledger.js, db/schema.sql (open_round's 400/hour rule), Caddyfile, test/integration-box/server.test.mjs, demo/load.mjs. Never open a file named .env. Never commit. Work only in this worktree.

Decisions (do not redesign). All limits are constants at the top of a new server/limits.js with env overrides, and every refusal is one frame `{type:'error', code:'rate_limited', retry_ms}` or a socket close with code 4429, logged once per minute per IP at most.
1. Client IP: `CF-Connecting-IP` when present, else the first `X-Forwarded-For` entry, else the socket address. Trust the headers only when `TRUST_PROXY=1` (default 1 in .env.box.example, documented; 0 in tests).
2. Per IP: at most 20 open sockets; at most 30 new socket connections per minute; at most 10 new anonymous players per 10 minutes (an `auth` without a valid token); at most 5 `request_otp` per 10 minutes and 3 per email per 10 minutes (the email one already exists in SQL: keep it, add the IP one in memory); at most 200 frames per minute per socket, and a frame larger than 4 KB closes the socket.
3. Per socket: `play` at most 1 per 4 s (a round is 5 s; the SQL 400/hour rule stays as the backstop); `leaderboard`/`tasks`/`get_me` at most 1 per second each.
4. Counters live in memory in server/limits.js (sliding windows by IP and socket), cleaned every minute; nothing in the database. `/status` gains `limits: {ips_active, refusals_1m, blocked_ips}`.
5. An IP that trips the socket-connection limit five times in ten minutes is blocked for 15 minutes (new connections dropped before the upgrade); the alerts module posts one line when the block list is non-empty and again when it clears.
6. Nothing changes for kiosks except the per-frame limits (a kiosk plays one round per 5 s anyway).
7. From the red team (docs/reports/redteam.md D3, D4, D10): (a) `request_otp_code` marks every earlier unused code for the same email as used when it issues a new one, so only the latest code verifies; (b) `readJsonBody` in server/index.js rejects a body over 4 KB with HTTP 413 and stops reading (count bytes as chunks arrive, destroy the request past the cap), and `/api/*` gets the same per-IP connection window as sockets (30 per minute); (c) kiosk `auth` attempts count against the per-IP anonymous-player window (10 per 10 minutes) so secret guessing is throttled, and a failed kiosk auth closes the socket with 4401.
