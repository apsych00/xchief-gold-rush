Never open a file named .env. Never commit. Work only in this worktree. Kiosks are out of scope: nothing here touches kiosk auth.

Decisions (do not redesign):
1. Table `public.devices(id uuid primary key default gen_random_uuid(), created_at, last_seen_at, first_ip inet, ua text)`. `players.device_id uuid references devices(id)`; `task_claims.device_id uuid`.
2. On a web `auth` frame the client may send `device` (an opaque device token). Format `<deviceId>.<hmac>` signed with PLAYER_TOKEN_SECRET like the player token, no expiry. If absent or invalid the server creates a device row and returns a new device token on `welcome` as `device`. The client stores it in localStorage under its own key, separate from the player token, and never clears it on sign out (sign out clears only the player token). A new anonymous player created on a socket carrying a valid device token gets that `device_id`.
3. `last_seen_at` and `first_ip` (from Cloudflare's CF-Connecting-IP or X-Forwarded-For, else the socket address) are updated on every auth, `ua` on first sight only.
4. Rewards are once per device OR per verified email: `claim_task` and `free_refill` refuse with `already_claimed` / `already_refilled` when a claim exists for the same task by any player on the same device_id, or by any player with the same verified email. Implement in SQL with a unique partial index on `task_claims (task_id, device_id)` plus the existing per-player check, and an email check via the players join. Anonymous players whose device token is missing are treated as one device per player (no cross-player block) so nothing breaks for old clients.
5. `me` gains `device_id` (own only). `/status` gains `devices24h` (count of devices seen in 24 h). Nothing identifies a device to other players.
