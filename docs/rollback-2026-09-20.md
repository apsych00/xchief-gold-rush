# Rollback: the 2026-09-20 deploy and the move to main

On 2026-09-20 the box stopped building from `dev` and started building from `main`, and the
337 commits that had accumulated on `dev` shipped in one go. This is how to undo any part of it.

## Where things stood before

| | |
| --- | --- |
| Box branch | `dev` |
| Box commit | `6ddd1fa` |
| `main` (all remotes) | `3b51d9a`, tagged `main-before-dev-merge` |
| Backups on the box | `~/backups/db.20260920-120856.sql`, `~/backups/env.box.20260920-120856`, `~/backups/state.20260920-120856.txt` |

`main` had nothing on it that was not already on `dev`, so the merge was a fast-forward. Nothing
was overwritten and no history was rewritten - which is what makes all of this reversible by
moving a ref rather than by reconstructing anything.

## Undo the deploy only, keeping main as the deploy branch

```
ssh goldrush
cd goldrush
REPO_DIR=$HOME/goldrush deploy/rollback.sh 6ddd1fa
```

`rollback.sh` leaves the repo on a detached HEAD deliberately, and `deploy.sh` notices that and
skips its own fetch/checkout, so a later routine deploy will not silently undo the rollback. To
come back to the branch tip afterwards: `git checkout main && REPO_DIR=$HOME/goldrush
deploy/deploy.sh`.

## Undo the move to main as well

```
ssh goldrush
cd goldrush
git checkout dev
DEPLOY_BRANCH=dev REPO_DIR=$HOME/goldrush deploy/deploy.sh
```

`DEPLOY_BRANCH=dev` is only needed until the committed default is changed back. The default now
lives in `deploy/deploy.sh`, `deploy/autodeploy.sh` and `deploy/install.sh`.

## Put main back where it was

```
git checkout main
git reset --hard main-before-dev-merge
git push --force-with-lease nightmareinc main
git push --force-with-lease apsych main
git push --force-with-lease origin main
```

Only do this if `main` genuinely needs to go backwards. Anyone who has already pulled it will
have to reset too.

## Restore the database

The dump is a plain `pg_dump` of the whole database, taken before the deploy.

```
ssh goldrush
cd goldrush
docker compose --env-file .env.box exec -T db psql -U postgres -d postgres < ~/backups/db.20260920-120856.sql
```

Worth knowing: the deploy applied no new migrations, so the schema did not change and the
database almost certainly does not need restoring. The dump is insurance, not a step.

## Restore the environment file

Two keys were added to `~/goldrush/.env.box` during this deploy:

```
ELASTIC_CLAIM_TEMPLATE_ID=gold-rush-gift
PUBLIC_URL=https://goldrush.xchief.academy
```

`PUBLIC_URL` was not a new feature so much as a missing one: the kiosk's WON-screen QR code and
the `{claim_url}` line in the gift-card email are both built from it, and building either
without it throws. To go back: `cp ~/backups/env.box.20260920-120856 ~/goldrush/.env.box` then
`docker compose --env-file .env.box up -d server`.

## What actually shipped

The headline changes, all of which had been signed off on the local stack first:

- URL routing for the five screens, so the back button retraces them instead of leaving the site
- the Afghanistan landing page at `/af/` removed (tagged `af-landing-removed` for later
  extraction - see that tag's own message)
- the gift-card email wired to the `gold-rush-gift` Elastic template
- everything else that had accumulated on `dev` since `3b51d9a`

`https://goldrush.xchief.academy/af/` now serves the game's own page rather than the landing
page, since Caddy falls back to `index.html` for unknown paths.
